# User Subscription (Отмена подписки) 📅

Этот пример демонстрирует типичную проблему Anemic Domain Model (Анемичной модели предметной области), когда логика работы с сущностью выносится в сервисы, а сама сущность становится "мешком с данными" из геттеров и сеттеров.

## ❌ Проблема (`bad.php`)
Сервис `SubscriptionService` запрашивает у объекта подписки его статус через `getStatus()`, проверяет его, а затем меняет статус через `setStatus()`. Если это же действие потребуется сделать из админки, другой разработчик может забыть проверить текущий статус, и отменит уже отмененную подписку. Бизнес-логика размыта.

## ✅ Решение (`good.php`)
Скажи объекту, что нужно сделать (Tell), а не спрашивай его состояние (Don't Ask). Сервис вызывает метод `$subscription->cancel()`, а вся логика валидации и изменения состояния инкапсулирована внутри класса `Subscription`. Объект сам защищает свои инварианты.
