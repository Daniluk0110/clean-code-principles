# Object Calisthenics 🏋️‍♂️

Объектная гимнастика — это набор из 9 правил программирования, которые помогают писать более качественный, читаемый и поддерживаемый объектно-ориентированный код.

## Основные принципы (некоторые из них)

### 1. Только один уровень вложенности на метод
Слишком много уровней вложенности (if внутри foreach внутри другого if) делает код сложным для понимания. Старайтесь выносить логику в отдельные небольшие методы.

### 2. Не используйте ключевое слово ELSE
Использование `else` часто указывает на отсутствие стратегии Early Exit или сложную условную логику. Почти любой `else` можно заменить на `return` или полиморфизм.

### 3. Используйте первоклассные коллекции (First Class Collections)
Любой класс, содержащий коллекцию, не должен содержать других свойств. Это позволяет инкапсулировать логику работы с набором элементов (фильтрация, подсчет, валидация) в одном месте.

### 4. Одна точка на строку (Закон Деметры)
Не следует вызывать методы у объектов, которые вы получили через другие методы (например, `$a->getB()->getC()->doSomething()`). Объект должен говорить только со своими непосредственными «друзьями».

### 5. Не сокращайте имена
Если вы чувствуете необходимость сократить имя, возможно, ваш метод или переменная делают слишком много.
